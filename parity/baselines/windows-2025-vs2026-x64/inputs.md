# Inputs for Windows Server 2025 / Visual Studio 2026 x64

What the pinned provisioning scripts fetch, what pins them, what cannot be reproduced locally, and what
has drifted. Checked on 2026-10-19 against `actions/runner-images` commit
`ee1ff4569e381a9649b400338bdc8ceb7e18a80e`. Nothing here was downloaded or executed except plain text
metadata (manifests, API JSON). P03 turns this list into verified artifacts.

## What upstream pins and what it does not

- Upstream rarely commits installer hashes. The fixed values found are these
  (details below): Android command line tools (URL and SHA-256 in
  the toolset), Service Fabric runtime and SDK (SHA-256 in the toolset), MySQL's Visual C++ redistributable
  (literal SHA-256), the Windows-Containers `install-docker-ce.ps1` helper (pinned to a commit, no hash),
  Docker and Docker Compose versions (toolset).
- Most hash checks compare a download against a hash **fetched at build time from the same vendor**
  (column "integrity" shows `SHA256/512 check`). That detects corruption, not a changed vendor release.
  P03 must record the resolved version, URL and hash at the time of each fetch.
- Several installers rely on an Authenticode subject check only, or on a vendor redirect
  (`aka.ms`, `go.microsoft.com/fwlink`). Those resolve to whatever the vendor serves today.
- Versions come from the toolset for some tools and from "latest" queries for others (column "floating").
  A rebuild at a later date does not reproduce the Readme. The upstream `README.md` at the pin says so as well
  ("Preinstallation Policy": some tools always install the latest at deployment time).
- The column flags in the table are heuristics over script text. They name what to read first. They are not a
  complete audit of every download.

## NEEDS EXTERNAL AUTHORIZATION or NOT REPRODUCIBLE LOCALLY

Each item is a blocker, not an omission (PLAN, "Baselines"). None is resolved by P01.

1. **Azure Marketplace base image.** `MicrosoftWindowsServer:WindowsServer:2025-Datacenter-g2`
   (S7 locals). It exists only in Azure, with Azure agent, drivers and image servicing. A local Hyper-V guest
   built from other media is a different base. The Readme's OS build `10.0.26100 Build 33438` reflects that
   image plus Windows Updates at build time.
2. **Windows Server 2025 media and activation.** Lawful installation media, edition, product key or
   volume activation and the licence for running it in a lab are owner decisions. Redistribution of the media
   or a built image may be restricted. Record the terms before any acquisition (ACCEPTANCE: baseline/provenance).
3. **Windows Updates level.** Install-WindowsUpdates.ps1 installs every offered update except `KB5034439`,
   twice (before and after a reboot). The KB list is not recorded in the Readme. Reproducing build 33438 needs
   a matching update catalog state, which Microsoft supersedes over time.
4. **Visual Studio 2026 Enterprise.** Channel `stable` with no pinned layout. The bootstrapper serves the current
   stable build, not 18.10.12224.181. Workload versions in the Readme mix 18.9.x and 18.10.x. Enterprise
   edition entitlement, product key or subscription for a non-GitHub host is not established by the scripts, and
   the install passes no key. It runs with `--allWorkloads --includeRecommended --nocache` and removes
   `Component.CPython3.x64` (Install-VisualStudio.ps1, VisualStudioHelpers.ps1).
   Visual Studio Marketplace extensions (SSIS, Analysis Services and Report projects, Installer Projects,
   Service Fabric, WiX VS extension) download by marketplace item name (VisualStudioHelpers.ps1) and carry their
   own terms.
5. **Windows 11 SDK 10.0.26100 and Windows Driver Kit.** Fetched through redirects
   (`go.microsoft.com/fwlink`) with an Authenticode check only. WDK and its Visual Studio extension are
   Microsoft-licensed.
6. **Vendor "latest" feeds with no hash source in the repository.** Examples seen in the table: Azure Cosmos DB
   emulator (`aka.ms/cosmosdb-emulator`), DacFx (`aka.ms/dacfx-msi`), SQL OLE DB and SQL PowerShell tools,
   Web Platform Installer, WinAppDriver, Google Chrome standalone installer, Edge and its driver, Firefox and
   Gecko, Selenium, IE driver, Miniconda, MSYS2 latest release, MongoDB `current.json`, Haskell ghcup,
   Chocolatey community feed packages. The version actually installed on 2026-10-07 is recorded in the Readme
   only. Reproducing it needs the exact installer files to be retained at the time of the first lawful fetch.
7. **Licence acceptances made by the scripts** (the rig operator inherits them): Android SDK licenses are
   written from an embedded archive (Install-AndroidSDK.ps1 line 96), Service Fabric `/accepteula`, SQL OLE
   DB `IACCEPTMSOLEDBSQLLICENSETERMS=YES`, MSYS2 `--accept-messages`.
8. **Credentials baked into the image.** The Readme documents a default PostgreSQL password and the scripts
   set `PGUSER` and `PGPASSWORD` machine-wide. A parity candidate must reproduce the same observable
   behaviour without committing the value. Obtain it from the running hosted job or the upstream Readme, never
   from chat or this repository.
9. **Build-only secrets and identities.** Packer authentication variables (client certificate, JWT, OIDC
   token), the `installer` account password and WinRM settings are supplied by GitHub's pipeline and are not in
   the repository. Not needed for a local build, listed so nobody searches for them.
10. **Nested virtualization and Hyper-V features.** Windows features include Hyper-V, Containers and
    VirtualMachinePlatform (toolset `windowsFeatures`). The lab host must expose nested virtualization to the
    guest. Needs an authorized, measured lab (PLAN, "Starting point").
