# Inputs for Ubuntu 24.04 x64

What the pinned provisioning scripts fetch, what pins them, what cannot be reproduced locally, and what
has drifted. Checked on 2026-10-19 against the build commit `7e7dc1bcc0ef464e5e315a2b4c33609590c6cffe`
(template and toolset in `sources/build-commit-7e7dc1b/`; the scripts are identical at the candidate `ee1ff4569e381a9649b400338bdc8ceb7e18a80e`). Nothing here was downloaded or executed except plain text
metadata (manifests, API JSON). P03 turns this list into verified artifacts.

## What upstream pins and what it does not

- Upstream rarely commits hashes. Fixed values found: a SHA-512 for the `libicu70` `.deb` (configure-dpkg.sh),
  Docker Client and Server 28.0.4, Docker Compose 2.38.2 (toolset), CMake 3.31.6 (toolset, with a documented
  review date), Azure CLI and other tool versions chosen by the apt or vendor feed.
- Most downloads compare against a checksum **fetched at build time from the same vendor** (column
  "integrity" shows `SHA256/512 check`) or rely on an apt or GPG repository key. That detects corruption, not a
  changed vendor release.
- The base image is selected with `source_image_version = "latest"` (variable default), so the Canonical
  Marketplace image moves at every build (U14).
- Versions come from the toolset for some tools and from "latest" queries for others (column "floating").
  A rebuild at a later date does not reproduce the Readme. The upstream `README.md` at the pin says so as well
  ("Preinstallation Policy": some tools always install the latest at deployment time).
- The column flags in the table are heuristics over script text. They name what to read first. They are not a
  complete audit of every download.

## NEEDS EXTERNAL AUTHORIZATION or NOT REPRODUCIBLE LOCALLY

Each item is a blocker, not an omission (PLAN, "Baselines"). None is resolved by P01.

1. **Azure Marketplace base image.** `canonical:ubuntu-24_04-lts:server`, version `latest` at build
   (U14). The kernel in the Readme is `6.17.0-1022-azure`, an Azure-flavored kernel, and the image carries the
   Azure Linux agent (`waagent`, deprovisioned at the end). A local guest from a different Canonical image is a
   different base. The build date of the base is not recorded.
2. **Superseded apt versions.** The Readme lists exact apt package versions (74 packages plus the OS, kernel and
   systemd versions). The live Ubuntu archive keeps only current pocket versions. P03 must retain the `.deb` files or
   an archive snapshot at the first lawful fetch. Availability of an Ubuntu snapshot service for these dates is NOT
   VERIFIED here.
3. **Vendor package repositories added during the build** (configuration removed afterwards, versions not
   archived): Microsoft (`packages-microsoft-prod`, Azure CLI, Edge, PowerShell), Docker, PostgreSQL (`apt.postgresql.org`),
   Google Cloud CLI, Adoptium Temurin, Kubernetes (`pkgs.k8s.io`), packagecloud (git-lfs), Ubuntu archive pockets. Keys
   are downloaded at build time.
4. **Proprietary or separately licensed components.** Google Chrome (`google-chrome-stable_current_amd64.deb`
   plus a Chromium snapshot download), Microsoft Edge and its driver, Microsoft packages (PowerShell, Azure CLI,
   .NET), the Android SDK (Google licence terms), Docker Engine and MySQL (Oracle, via the Ubuntu archive). Licence
   terms and redistribution limits must be recorded before any acquisition. The scripts export `ACCEPT_EULA=Y`
   globally, which is an acceptance the rig operator inherits.
5. **Vendor "latest" feeds with no hash source in the repository.** Examples seen in the table: AWS CLI zip, Session
   Manager plugin, Azure CLI install script, azcopy `aka.ms` link, Bicep, kubectl `stable.txt`, minikube, Kustomize,
   Helm install script, Pulumi `latest-version`, Packer `latest`, Swift releases API, Miniconda `latest`, nvm install
   script, `n`, Homebrew install script, Rustup (`sh.rustup.rs`), ghcup and Stack install scripts, Composer installer,
   PHPUnit phar, Gradle versions list, Maven metadata, Julia `versions.json`, Google Cloud CLI, CodeQL bundle
   releases, AWF and Copilot CLI releases, `action-versions`. The versions installed on 2026-10-12 are recorded in the
   Readme only. Reproduction needs retained copies from the first lawful fetch.
6. **Floating container images.** Six images are pulled as `:latest` from `ghcr.io` (see README). Digests were not
   recorded upstream. Their content cannot be reproduced after those tags move.
7. **Credentials baked into the image.** The MySQL root password is set by the build script and documented in the
   Readme (masked in `inventory.json`). A parity candidate must reproduce the observable behaviour without
   committing the value.
8. **Build-only secrets and identities.** Packer authentication variables, the `installer` account and cloud-init
   settings come from GitHub's pipeline and are not in the repository.
9. **Nested virtualization and container behaviour.** Docker, Podman, Buildah, Kind and Minikube run on the hosted VM
   (Readme Tools). Their parity depends on kernel features, `/run/docker.sock`, cgroup version, sysctls and storage tuning
   listed in the README. A WSL or container-based guest shares the host kernel and may not provide them (the audit
   already flags Sysbox on the WSL kernel). Needs an authorized, measured lab (PLAN).
